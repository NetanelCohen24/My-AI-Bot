# Depot · ניהול מלאי למפיץ

מערכת Web לניהול מלאי לחברה שמחזיקה מחסן ומוכרת לחנויות: מלאי ותנועות, אצוות ותוקף, הזמנות לקוחות, רכש מספקים, ספירות והחזרות, וייבוא מאקסל. React + Tailwind, ממשק עברית RTL.

## הרצה

```bash
cd depot
npm install
npm run dev      # http://localhost:5173
npm test
npm run build
```

## איפה נשמרים הנתונים

| מצב | מתי | הערות |
|---|---|---|
| **מקומי** (ברירת מחדל) | בלי הגדרות | נשמר בדפדפן הנוכחי בלבד. מתאים לניסיון. מומלץ "הורדת גיבוי" מדי פעם. |
| **Supabase** (רב-משתמשים) | כשמוגדר חיבור | כל העובדים רואים את אותו מלאי בזמן אמת, עם כניסה באימייל וסיסמה. |

### חיבור Supabase (חינמי)
1. יוצרים פרויקט ב-[supabase.com](https://supabase.com).
2. ב-**SQL Editor** מריצים את `supabase/schema.sql`. הסקריפט יוצר את הטבלאות, את ההרשאות (רק משתמשים מחוברים) ואת העדכון בזמן אמת, ואפשר להריץ אותו שוב בבטחה.
3. ב-**Authentication → Providers → Email** מכבים את Sign-ups. ב-**Authentication → Users** מוסיפים משתמש לכל עובד.
4. ב-Vercel (Project → Settings → Environment Variables) מוסיפים:
   - `VITE_SUPABASE_URL` = Project URL
   - `VITE_SUPABASE_ANON_KEY` = anon public key

   אחר כך עושים Redeploy. לחלופין אפשר להדביק את שני הערכים במסך **הגדרות** באפליקציה.

## לוגיקה
- **המלאי מחושב תמיד מיומן התנועות** (קליטה, משלוח, החזרה, ספירה, גריעה, יתרת פתיחה) ולא נשמר כמספר. תנועות לא נמחקות; טעות מתקנים בתנועה נגדית.
- **זמין** = מלאי בתוקף פחות הזמנות לקוחות פתוחות (מאושרות או בליקוט).
- **משלוח לפי FEFO**: האצווה שתפוגתה הכי קרובה יוצאת ראשונה, ואצווה שפג תוקפה לא תוקצה. המשלוח מתבצע רק אם כל השורות זמינות.
- **הצעת רכש**: נקודת ההזמנה היא הגבוהה מבין מינימום המוצר לבין צריכה יומית (ממוצע 30 יום) × (ימי אספקה של הספק + 3). כשהמלאי הזמין יחד עם מה שבדרך מהספקים יורד מתחת לנקודה, המערכת מציעה כמות להזמנה.
